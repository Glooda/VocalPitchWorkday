# VocalPitchWorkday

为唱见开发的音准可视化工具：导入原唱和你的干音，在同一条时间线上
看到三条轨道 —— 原唱的音准、你的音准、两者叠在一起的样子，可以放大到单个音符
甚至单个颤音周期去看。

**当前状态：M1（看见）完成；M2 的 P1（多轨会话）、P2/P3（切分·复制·淡变·增益·波纹删·离线混音播放）、
「节拍」这一块（顶部标尺 / 对拍网格 / BPM 识别 / 一键适配）、P6 计划1（整幅画布背景网格）、
P6.2（跨轨拖拽 + 文件拖入）、P7（录音）、P8 的 R0+R1（边播边录 / 多轨武装 / 延迟补偿 / 实时波形）
与 **界面重做**（菜单栏 / 工具栏分组 / 传输条瘦身 / 幽灵行 / 主题 token / banner / 脏标记）、
**P9（选择唯一真源 / 静音独奏统一判据 / 录音预览块）**完成；逐音符评分未开始。**

## 跑起来

```powershell
# 1. 依赖（Python 3.10+；已在 3.14 上验证）
python -m pip install -r requirements.txt

# 2. 先跑算法自检（不需要界面、不需要音频文件）
python -m vp.selftest

# 3. 打开界面
python run.py
```

自检应当输出五项 PASS（单音精度 / 准音命中率 / 颤音保真 / 清音判定 / 对齐精度）。
**颤音保真这一项是核心**：它证明后处理没有把 5.5 Hz 的颤音抹平，也就是
"飘"这件事还看得见。

## 怎么用

1. `Ctrl+1` 导入原唱（若是成品混音，先点「提取人声」，需要装 demucs）；
2. `Ctrl+2` 导入你的干音；
3. `Ctrl+T` 加一条空轨，再「导入到所选轨」，可以放和声、第二条干音等；
4. **拖波形条**移动 clip，**拖左右 8px 边缘**裁剪（下面的音高条只能拖平移视图，
   避免误触）；拖动时靠近播放头 / 别的 clip 边缘会吸附，按住 `Alt` 临时关掉；
5. `Ctrl+滚轮` 以光标为锚点缩放时间轴，滚轮左右滚动，`Alt+滚轮` 缩放音高轴，
   双击或 `F` 适配视图；
6. `Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做，`空格` 播放/暂停，`Delete` 删除所选 clip；
7. 编辑：`S` 在播放头切分、`Ctrl+D` 复制到后面、`Ctrl+Shift+Del` 波纹删除
   （同轨后面的片段自动接上）、`[` / `]` 增益 ∓1 dB；右键 clip 或点工具栏
   「编辑 ▾」还有「设置增益…」「设置淡入/淡出…」；
8. 每条轨左边有 `M` / `S`，静音与独奏直接作用于播放。
9. 节拍：`Ctrl+B` **一键适配**（从原唱检测 BPM 与拍号，写好首拍并缩放到 4 小节），
   底部会显示 `♩ 120.0 BPM · 4/4 · 首拍 +0.30s · 可信 3.20`。工具栏「节拍 ▾」里还能
   只检测 BPM、手工「设置 BPM 与首拍…」、**点拍取速**（跟着歌敲空格）、`G` 开关网格、
   清除节拍。最上面那条是**小节标尺**，单击/拖动可移动播放头，双击直接改节拍。
   网格会跟着缩放自动降级（拍线太密就退到小节线，再退到 2/4/8 小节）。
10. **录音**：先在左侧点一条轨道（选中那条会高亮），把播放头挪到要插入的位置，
   点「● 录音」或按 `Ctrl+R` 开始，再按一次停止。录到的 wav 会**自动插到这条轨道
   的播放头位置**，走一遍音高分析，作为一条 clip 进撤销栈 —— 所以录坏了 `Ctrl+Z`
   就没了。录音条旁边的「输入 ▾」可以选输入设备（麦克风/声卡）与 44.1/48 kHz。
   录音时播放会自动暂停（免得把伴奏录进去），红色 `REC` 显示时长与电平。
11. **拖到别的轨道**：按住波形条直接往下拖，目标行会高亮、出现竖直虚线与时点气泡，
   松手才真正换轨（拖动中只在本行跟手，这样事件不会在被重建的行里断掉）。
   目标轨里有锁定的 clip 时会拒绝换轨、只改水平位置，状态栏会说一声。
12. **把文件拖进窗口**：wav/flac/mp3/m4a 落到某一行 = 插到该行的时间点（允许重叠）；
   落在空白区 = **每个文件各建一条新轨**；整批导入包在一次撤销里，失败一个就整批放弃，
   不会留下半截空轨。拖一个 `*.vpsession` 进来就是打开会话。

播放是**离线混音**：按播放前先把整条会话按 trim / 淡变 / 增益 / 静音独奏烘成
一条临时 wav（`%TEMP%\VocalPitchWorkday\mix.wav`），再用单流播出。所以播放和画面上看到的
完全一致，不会出现"图里裁掉了可耳朵里还在放"。改了会话后混音作废，空闲 0.8 秒
自动重烘，下次按播放是瞬间出声。

同版伴奏的话点「自动对齐」先粗对，剩下用鼠标拖比用数字框调更顺手。

放大到 0.5 秒以内时，波形会从 min/max 包络自动切回原始采样折线 —— 否则每个像素
仍覆盖一个 11.6 ms 的桶，放大多少倍都是实心方块，看不出波形。

## 界面布局（2026-11-15 重做）

从上到下：**菜单栏**（文件/编辑/视图/节拍/录音/帮助）→ **工具栏**（导入三连 │ 自动对位 │
适配视图·显示网格 │ 提取人声）→ **小节标尺** → **编辑层**（轨头列 + 画布）→
**叠加对比**（24px 标题行 + 「原唱／我／叠加」三态）→ **传输条**（≤7 个控件）→ **状态栏**。

- **一个命令只有一个入口**：所有动作注册在 `vp/ui/actions.py::ActionRegistry`，菜单、工具栏、
  空态卡按钮复用同一个 `QAction`（`test_ui_opt.py` 断言无重复对象、无重复快捷键）。
  以前 `act_grid` 被创建两次导致 `G` 键失效，就是这条规则的反例。
- **颜色只有一个来源**：`vp/ui/theme.py`，组件里不再写内联 hex（自检会 grep）。
  主题由 `theme.apply(app)` 装到 QApplication，真程序 / 离屏测试 / 截图脚本配色一致。
- **末尾有幽灵行**：滚动区末尾永远有一条「＋ 添加轨道」虚线行 —— 它是真按钮，
  Tab 可达、回车触发。（0 轨时曾经浮在画布中央的引导卡已按需求删除。）
- **未保存看得见**：任何改动让标题出现 `●`、状态栏写「未保存」；关窗会问「保存／不保存／取消」。
- 窗口 <1100 px 工具栏自动收成纯图标。

对拍网格分三层：轨内淡拍线、行间通高竖线（画在画布父控件上，所以行间空隙也有）、
顶部标尺小节数字；缩放变小自动退级（拍 → 小节 → 2/4/8 小节）。

## 关键设计（改代码前值得先知道）

- **纵轴是浮点 MIDI**，不是 Hz 也不是 cents。一单位 = 一个半音，等距，能直接
  对上钢琴键。
- **后处理窗口 ≤ 50 ms**。人声颤音 5~7 Hz，窗口一长就被抹平，「抖」这个维度
  就没了。
- **清音存 NaN，不存 0**。0 Hz 在 log2 里是负无穷，会把整张图拉爆。
- **对齐只做全局偏移**，不做 DTW：同版伴奏速度一致，DTW 只会把抢拍的真实
  信息抹掉。
- **UI 不碰算法**：界面只认 `PitchTrack` 和 `analyze_file`，换引擎不改界面。
- **节拍是常数 BPM**：不做 rubato 跟随、不中途变速 —— 这条已写进方案文档，
  不是没做，是故意不做（自动跟随反而会把拖拍洗白）。
- **网格自己画线，不用 `showGrid`**：轴刻度是等距的，跟拍子没关系；线必须落在
  `offset + k*period` 上，只能自绘。文字标签更要小心，见下面第 9 条坑。
- **画布背景网格画在父控件上，不画在各行里**：每行是独立的 GraphicsScene，图元
  无法跨行共享，而行与行之间的空隙不属于任何一行。因此由 `TimelineCanvas`
  （滚动区里的背景控件）一次画满整幅，行的波形/曲线不透明地盖在上面，就得到
  「线只在空隙里露出来」的效果。时间↔像素一律走 `TimelineGeometry`，任何控件
  坐标系都能换算，失败返回 nan 而不是抛异常。

画布背景网格（`tools/test_backdrop.py`，26 项全过）：先断言四块区域的数据区左边界
完全对齐（wave / 音高条 / 叠加轨 / 标尺，实测都是 0.0 px）；`plan_lines` 的数学
（8 s / 120 BPM = 16 条、首条是 0.25 s 的四小节线、2.25 与 4.25 s 是小节线）；
无节拍 / 非法跨度 / 宽度 0 / NaN 一律返回空表；缩到 5.00 px 每拍时自动退级
（60 条 < 240 条）。视觉部分直接扫像素：行间空隙的线与轨内拍线**逐列比对 35 列，
最大偏差 1.0 px**；放大到 56 条仍受控；关掉网格（`G`）后画布与轨内都是 0 列；
窗口 resize 后 48 列仍对齐。

跨轨拖拽与文件拖入（`tools/test_drag.py`，26 项全过）：轨 0 拖到轨 1 后 `clip.track == 1`
且起点按吸附落位；撤销回原轨原位置、重做再回目标轨（靠 `MoveClipCommand(track0=...)`
构造时就固定原轨 —— 拖动中 clip 已经换过轨，命令第一次 redo 再读会读成目标轨）；
拖动过程中撤销栈条数不变、松手才 +1；目标轨被锁定时只改水平位置；拖到叠加轨松手
落到最后一条轨且不建新轨；三个 wav 拖到空白区 = 三条新轨、每轨一 clip、一次撤销全消失；
单个 wav 落在 12.4 s 处实测 12.40 s；`.txt` 不受理；损坏 wav 不建空 clip 且状态栏报错；
拖入 `.vpsession` 后轨数与 clip 数一致。

选定轨道录音（`tools/test_rec.py`，32 项全过）：16bit PCM 满量程/半量程/负半量程换算
（0 / 0.5 / −0.5 / ±1.0）；落盘 44.1 kHz 单声道 PCM_16、时长与内容往返一致；
指定了不存在的设备会**明确报错**而不是偷偷换默认麦克风；停止时未开始返回 None。
界面部分用替身录音器：`Ctrl+R` 开始/停止，按钮文字在「● 录音」与「■ 停止」之间切换，
录到的 2.0 s 素材插到**选中轨道的播放头位置**（实测 2.500 s）、整段未裁、带 171 帧音高、
进撤销栈且标题是「录音」、可撤销可重做、混音总长随之变长；关闭窗口时正在录音也不会崩。

P9（`tools/test_fix_p9.py`，34 项全过）钉住三件事：

- **选择只有一份真源**（`MainWindow.sel_uid`）。以前每行各存一个 `_selected_uid`，
  切分/删除却按「行号最小的有选中行」去取，跨轨时就会切错块；`selected_uid` 是只读
  property，`select_all` 和 Esc 赋值时抛 `AttributeError` 被 Qt 吞掉，所以 Esc 一直清不掉。
- **静音/独奏只有一个判据**（`Session.is_audible()`），渲染置灰与混音都读它；
  播放中按 M/S 不热切换单流播放器（会断音 0.2~0.3 秒），只标记待重混并提示，
  暂停/停止时立刻重烘。
- **录音期间会话里要有东西在长**：`begin_take()` 放一块 `provisional` 预览块
  （不进撤销栈、不混音、不序列化，也不计入状态栏的「块」数），`grow_take()` 跟着 tick
  撑长，停止时 `end_take()` 换成真 clip，再异步补音高曲线。

音高条空白（`tools/test_pitch_guard.py`，17 项全过）是"看上去像没渲染、其实是数据坏了"
的典型案例，值得记住整条链：

- 用户看到的现象：原唱轨有波形、音高条全空；同一会话里另一条（干净的 wav 干音）曲线正常。
- 三种可能先分清：① 没分析 ② 分析了但没有浊音帧 ③ 有数据但落在纵轴之外。
  `python tools/diag_pitch.py <音频>` 或 `--session <会话>` 会把每一层的数字都打出来。
- 实际原因是 ③，而且纵轴是**倒置**的（`24.00 .. -101.89`），一条线都画不出来。
- 追问为什么音高会是 -131：长素材的八度修正逐帧累积（见调试坑第 15 条）。
- 现在界面不再静默：没有曲线时行内会写明「音高还没分析完或分析失败」或
  「没检测到人声基频（伴奏太重？先「提取人声」再分析）」，右键还有「重新分析音高」。

做 P2/P3 时抓到的两个真问题：

4. `load_audio` 对每条素材各自峰值归一化到 0.98 —— 混音里轨间电平关系被抹平，
   安静那轨会被偷偷拉上来。现在 `load_audio(..., do_normalize=False)` 供混音用。
5. 淡出曲线被写反（`linspace(1,0)[::-1]` 变成渐强），淡出段反而最响，靠数值自检抓到。
6. **Windows 上不能覆盖播放器正打开着的 wav**：早期固定写 `mix.wav`，空会话时先烘出
   一条 0.05 s 的静音，播放器一装就把那个文件锁住，之后每次重混都 `PermissionError`
   （界面上显示"混音失败：拒绝访问"）。现在空会话根本不烘，且每次重混换一个
   `mix<N>.wav`，切过去之后再删旧的。
7. pyqtgraph 的 `ev.screenPos()` 给的是 **QPointF**，`QMenu.exec()` 只收 QPoint，
   右键菜单会抛 `TypeError`。统一用 `MainWindow._as_point()` 转换。
8. **pyqtgraph 0.14 的 `ViewBox` 没有 `viewGeometry()`**（那是 QWidget 的 API）。
   它被包在 try/except 里、异常时 `return None`，结果网格静默不画 —— 界面上什么都不报。
   现在按 `boundingRect()` → `geometry()` → 800 依次退。
9. **不要在 ViewBox 的数据坐标里 `drawText()`**：14 秒铺满 1200 px 时，一个 8pt 的小节号
   会被横向拉成 90 倍，屏幕上是一片灰白色的「波形状」糊块。文字必须用带
   `ItemIgnoresTransformations` 的子图元（现在只画在底部叠加轨上，顶部标尺用自定义 AxisItem）。
10. **`mapFromView()` 只到父坐标系，不是场景坐标**。波形条加了 46 px 左内边距之后，
    `ViewBox.mapFromView()` 的结果与 `mapSceneToView()` 期望的输入差了整整 50 px
    （6 s 的 clip 上约 0.28 s）：边缘命中、拖动距离全部错位，症状是「点左边缘没反应、
    拖右边缘变成整体平移」。正确写法是 `mapViewToScene()` / `mapSceneToView()` 成对使用。
11. **`QGraphicsSceneMouseEvent.pos()` / `buttonDownPos()` 是 item 局部坐标**，
    而 `_hit()` / `mapSceneToView()` 要的是场景坐标；同理必须用
    `scenePos()` / `buttonDownScenePos()`。这两个坑是同一件事的两面：46 px 内边距
    之前恰好只有 ~1 px 偏移，所以老代码「碰巧能用」，加了音名轴就全线暴露。
12. **clip 起点不许是负数**。`mix[-8820:...]` 会被 numpy 当成"从末尾倒数"的环状切片，
    长度对不上就抛 `operands could not be broadcast together with shapes (8820,) (1127196,)` ——
    用户看到的是"按播放没声音，状态栏报混音失败"。来源是延迟补偿
    `start = 播放头 - 延迟`，在 0 附近起录会算出 -0.05~-0.2 s。
    现在 `Clip.__post_init__` 一处钳到 0、渲染再兜一层、录音落库时把落在时间线之外的
    那截 wav 头一起切掉；`out/mix_error.log` 会存完整堆栈。
13. **新增图元必须同时登记 `_drop_items`**。`wavepath`（波形竖线）和 `cap`（录音生长线）
    当初漏登记，删掉 clip/轨道之后它们还挂在 PlotItem 上继续画 —— 看起来就是
    "轨删了波形还在"。另外 `setParent(None)` 要放在 `hide()` 之后：一个还可见的控件
    被摘掉 parent 会变成独立顶层窗口，在 `deleteLater` 执行前悬在原处。
14. **行控件是复用的，身份信息不能只在构造时写一次**。删中间轨时后面的行 index 前移、
    控件不重建，`name/role/color` 缓存下来就会"画的是和声、头上写着我的干音"。
15. **八度修正不能拿"已经改过的"上一帧当参照**。`octave_fix_midi` 原本写
    `a, b = m[i-1], m[i]`，而 `m` 正是它自己正在改的数组 —— 一次 ±12 的调整会被下一帧
    继续沿用，逐帧累积。短音频（自检里的 3 秒正弦）看不出来，两分半的成品混音能一路漂到
    **-20 个八度**（实测该 mp3 的音高中位数 = -131.74，对应基频 2e-6 Hz）。
    连锁反应：`pitch_range` 算出 1% 分位 24、99% 分位 -101，`setYRange(24, -101)` 是
    **倒置范围**，于是"音高条整条空白、波形还在"（波形只依赖 peaks，不依赖分析）。
    现在参照物取原始值、修完用"滚动中值 + 全局中值"双参照剪枝，并加 [MIDI_LOW-12,
    MIDI_HIGH+12] 的音域闸门；`ENGINE_VERSION` 升到 0.2.0 让旧缓存自动失效。
    教训：**自检要有一条长输入的用例**，否则这类"越长越坏"的 bug 永远测不出来。
16. **同一个 46 px 左偏移不能加两次**。标尺原来用「46 px spacer + plot」来和轨道对齐，
    而 `hideAxis("left")` 并不会让 ViewBox 的数据区从 0 开始（pyqtgraph 仍按轴宽留偏移），
    两段叠起来数据区就比轨道行晚 46 px。症状很隐蔽：`setXRange(0, 100)` 之后
    `viewRange()` 回来 `3.92..103.92`（= 46/1174 × 100），顶部标尺的拍号与下方拍线
    整体错开半个格。改成 `setContentsMargins(46, 0, 0, 0)`（与 wave 条同一条路径）即对齐。

调试期踩到的坑（大半已成为回归测试的守门项）：

1. `np.log2(x, out=out[mask])` 里的 `out[mask]` 是**副本**，写进去全丢 → 整条曲线 NaN。
2. YIN 取「第一个低于阈值的 tau」会停在下降沿，产生约 20 cents 的阶梯误差；
   必须取**第一个局部最小**再做抛物线插值。
3. 分析窗长 1024（46 ms），若把窗起点当帧时间戳，估计值会整体滞后 23 ms，
   颤音段相位对不上，白丢十几 cents。现在按窗中心对齐。

## 已知限制

- **播放靠离线混音**：每次改完会话要重烘一条 wav（4 分钟双轨约 0.2–0.3 秒），
  改一下按一次播放会重新烘；连续拖动时不会实时重烘。
- 淡变目前只能填数字（右键菜单 / 编辑 ▾），还不能拖 clip 角上的手柄。
- 拖动跨轨时**视觉上只在原行跟手**，松手才落到目标行 —— 这是故意的（拖动事件握在
  正在被重建的行手里会断），代价是拖动中看不到「半透明预览」。
- **边播边录已支持**（播放中按录制，clip 起点按按键那刻的播放头算，见 `vp/rec_session.py`），
  但倒计时/punch in-out、循环多 take、loopback 延迟校准向导还没做。
- **播放中改静音/独奏不会立刻重混**（单流播放器换文件会断音），按提示停止/暂停后生效。
- 录音中禁止切分/删除/保存会话，武装状态也不能改 —— 否则「这次录了几条、落在哪」无法解释。
- 波形是每像素一根 min→max 竖线；缩到 0.5 秒以内自动切回原始采样折线。
- 录音是 16 bit 单声道，44.1/48 kHz 二选一；没有监听回放
  （用声卡监听时人耳会听到延迟，需要自己用声卡直通）。
- 波形缩略图在持续音上会显示成实心带（每像素只有 min/max，没有细节），放大到
  0.5 秒以内才会切回原始采样折线。
- 混音是单声道单流，没有声像、总线效果、选区循环播放。
- 会话可以存成 `*.vpsession` 再打开，但音高曲线不存盘，打开后要重新分析一遍。
- 人声提取只接了 demucs（要 torch，约 2 GB）；轻量的 MDX-Net ONNX 后端还没写。
- RMVPE 适配器未用真实导出验证过，`CENTS_PER_BIN` / `BASE_CENTS` 需实测校准
  （方法见 `engine_api.md` 第 3 节）。
- 播放依赖 QtMultimedia，个别机器缺解码器时只能播 wav。
- 超长文件（>10 分钟）尚未做流式分析，内存占用按整段算。
